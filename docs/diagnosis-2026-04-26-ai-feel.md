# Pipeline AI 味問題診斷與改版建議

**日期**：2026-04-26
**問題**：research-publishing-pipeline 最近兩天（2026-04-24、2026-04-25）產出的文章被使用者點名「AI 味太重」。
**對照組**：手寫文章（如 `2026-03-29-與-ai-agent-生活後的三個啊哈.md`）與 mashbean-accent skill 的明確規範。
**樣本**：
- `2026-04-25-anesthesiologist-ai-agent.md`（麻醉科 + AI Agent）
- `2026-04-24-exile-network-state-coordination.md`（流亡 / Network State / Coordination）
- `2026-04-22-diaspora-social-movements.md`（流亡社群社運）

## TL;DR

最大問題不是「禁則沒抓乾淨」，而是 pipeline 從 writer prompt 開始就把「論證厚度」當成首要目標，**完全沒有把「mashbean 本人語氣」放進評分函數**。editorial pass 只在反向去除「AI 套路句」，沒有正向誘發 mashbean 的招牌句型、自嘲、跨領域比喻、括號吐槽、台語混搭。結果是一篇「乾淨、嚴謹、無人味」的研究稿，外觀很像他寫的——句長相近、會用「我」——但讀起來就是不對。

## 1. 症狀清單（從三篇實際成品中蒐證）

| # | 症狀 | 文中具體例子 |
|---|---|---|
| S1 | **「不在 X，而在 Y」** 的偽裝變體繞過禁則 | 麻醉文：「真正讓人耗損的，是身分切換不掉。」「真正壓垮人的是開刀房外那五層。」「真正承重的是契約—仲裁—資本保全這個三段結構。」（流亡文）。把「不是 A 而是 B」改寫成「真正的 X 是 Y」「答案不在 X，而在 Y」是同一個 AI 套路句的近親變體。 |
| S2 | **過度齊整的破折號夾注句** | 「真正的合法性來源，牽涉三種互相緊張、彼此卻無法拆開的維度——歷史延續、人民承認、國際承認」、「下面四類雜務都會碰到」、「真正的關卡是武裝協調、腐敗、代表性、國際承認」。三篇全部高密度使用 `——` 後接平行三件式，是 GPT-class 模型的指紋句型。手寫文幾乎不用破折號接列表，會用括號或逗號逐一鋪陳。 |
| S3 | **學術 / 法律審慎口吻包覆全篇** | 「請當定性整理來讀，別當成代表性調查或統計樣本」、「這個概念缺 RCT 直接驗證」、「這條因果鏈缺 RCT 直接驗證」、「這個區分比較接近規範性理想型，而不是經驗上乾淨的兩個陣營」、「具體百分比依研究設計、模型版本、prompt 條件差異極大，給單一數字會誤導讀者」。一篇 blog 文章自我標註「方法論風險」「樣本說明」「請理解為診斷層級錯位」，完全是論文 / 報告腔，是 critic agent 反饋循環過度寫進正文的痕跡。 |
| S4 | **完全沒有 mashbean 的招牌詞彙** | 三篇加起來，「啊哈」「嘻嘻」「颯爽」「家己」「歹勢」「超級懶」「歪腦筋」「圖一樂」「大哉問」「龍蝦」「三壁」「貼心怪」「動動嘴巴」「跌跌撞撞」「多轉一個彎」**全數 0 次**。lexicon.md 列了 60+ 個標誌詞，使用者每篇手寫平均落 3–6 個，pipeline 落 0 個。 |
| S5 | **沒有任何括號 meta 吐槽** | 整個三篇沒有出現一次「（遠目）」「XD」「（聽起來好像廢話）」「（達克效應中）」這類括號插話。手寫文每千字會出現 1–2 次。 |
| S6 | **沒有跨領域 / 文化梗錯置比喻** | 麻醉文用「個人交班員」是唯一接近的，但寫得像論文比喻附註，不是隨手丟出的政戰系統 / 整風 / 京劇 / RPG / 皮克敏這類 mashbean 標誌性錯置。 |
| S7 | **沒有預期 vs 結果的招牌句型** | 「我以為……結果……」「我想說……沒想到……」「於是我又……於是我又……」這個四拍／三拍敘事連鎖完全消失。三篇開頭都是論點型、不是經驗型。 |
| S8 | **結尾不是回望式感性收束，是論文式總結** | 流亡 NS 文結尾：「純以誌之，供自己日後回看這組比較時不要滑回光譜式敘事。」——「純以誌之」是對的，但前一句仍是論點而非情緒回望。麻醉文結尾「純以誌之，下班後這篇就是個人交班」雖然嘗試掛鉤生活，仍被前面 153 行的審慎報告腔壓住。手寫文的結尾是「能動性就回復了，因此一切都是最好的安排。」——五個字收住整段情緒；pipeline 的結尾仍在下結論。 |
| S9 | **段落節奏全是中長句，極少單句段落作節奏點** | 三篇通篇是 4–8 行的段落塊堆疊，幾乎沒有「一句話自成一段」的停頓。手寫文每千字會出現 2–3 次「真是颯爽。」「這讓我驚呼不已！」這種破格停頓。 |
| S10 | **第一人稱用得保守、沒有自嘲** | 「我一直覺得這組擺法本身才是問題」、「我有三個很務實的理由」——「我」是有，但是論述者的「我」，不是「家己很幸運」「身為超級懶」「歪腦筋動到 X」這種有溫度、有姿態、會自貶的「我」。三篇 0 次自嘲。 |

## 2. 根因分析（追溯到 pipeline 環節）

| 症狀 | 根因環節 | 具體在哪一段 |
|---|---|---|
| S1（「真正的 X 是 Y」變體） | `agent-writer.md` 禁則 + `run_editorial_pass.py` BANNED_PATTERNS | 兩處只攔截「不是…而是…」的字面，沒攔「真正的 X 是 Y」「關鍵不在 X，是 Y」「答案不在 A，在 B」這種同骨架變體。模型學會了「換皮」。 |
| S2（破折號夾注） | `agent-writer.md` 沒有禁則 / editorial pass 沒掃 | `——` 接平行三件式是 LLM 高頻指紋，pipeline 完全沒處理。 |
| S3（審慎報告腔） | `agent-critic.md` 反饋循環 + `agent-writer.md` 第二段「保留論證厚度」 | critic 要求「明確標出範疇限制」「標出工作假設」「標出推理品質」（見 critic 2a），writer 在改寫時把這些 critic 語言「直接寫進正文」而不是消化吸收。導致正文出現「請當定性整理來讀」「這條因果鏈缺 RCT 直接驗證」這類論文審稿語。critic 的 feedback 應該在 fact-check report 內部消化，不該成為 blog 正文的安全聲明。 |
| S4（無招牌詞彙） | **整個 pipeline 不知道 mashbean-accent skill 的存在** | `agent-writer.md` 完全沒提到 mashbean-accent；`specs/style-policy-zh.md` 是純禁則式（「不要這樣」），沒有正向 lexicon。writer 只被告知「不要報告腔」「節奏要像對話」，沒被給「請主動使用以下 60 個標誌詞中的 3–6 個」。 |
| S5（無括號吐槽） | writer prompt + style policy 都沒提 | 與 S4 同根，正向引導缺席。 |
| S6（無跨領域錯位比喻） | writer prompt 沒提；critic 反而會壓制 | critic 強調「理論套用是否恰當」「範疇滑移風險」，這對嚴謹研究是對的，但會勸退 writer 用「政戰系統 = AI agent monitoring」這類**跨領域錯位比喻**——而那正是 mashbean 風格的核心。critic 與 accent 在這個點上有結構性張力，pipeline 沒處理。 |
| S7（無「我以為…結果…」招牌句型） | writer prompt 沒提 | style-policy-zh.md 講「先論點後引用」「節奏要像對話」，但沒給「請使用『於是我就…沒想到…竟然…』這類三拍／四拍敘事連鎖」。 |
| S8（結尾論文式） | `agent-editor.md` 第 1 條「結尾是否有力（不是虛弱的『還需要更多研究』）」 | 這條把「無力結尾」識別出來，但沒指引「請用回望式感性收束」「請寫一句帶讀者走的句子」。editor 的修法是把無力結尾改成「有力的論點結尾」，剛好走錯方向。 |
| S9（無單句段落節奏） | writer + editor prompt 沒提 | 沒有「請允許並鼓勵單句自成段落」這個指令。 |
| S10（無自嘲） | 整個 pipeline 沒提 | mashbean-accent 自檢清單第一條「有沒有至少一處自嘲」，pipeline 0 個環節在檢查這件事。 |

**核心結構問題**：pipeline 的 reward function 是「研究正確性 + 禁則乾淨」，accent 的 reward function 是「像他本人」。這兩者目前是互斥的——critic 越嚴格，writer 越往論文腔靠。沒有一個環節在測「這篇讀起來像不像 mashbean」。

## 4. 改版建議（具體可執行）

### 4.1 Writer prompt 改寫（`prompts/agent-writer.md`）

**新增第 22–28 行（blog rewrite 段）**，把現在的：

```
- 開頭必須讓讀者知道這篇要回答什麼
- 先論點後引用，不要每段都從來源開始
- 保留論證厚度，但節奏要像對話
```

改為：

```
- 開頭用情境定錨，不寫總綱、不預告章節結構（mashbean 風格）
- 先論點後引用，不要每段都從來源開始
- 保留論證厚度，但節奏要像對話：長短句混雜，每千字至少 2 個單句段落作停頓
- 必須讀並套用 mashbean-accent skill（見 `/Users/mashbean/.claude/skills/mashbean-accent/SKILL.md`）
- 主動使用 lexicon.md 中 3–6 個標誌詞，自然分佈
- 至少一處自嘲、至少一處括號 meta 吐槽、至少一個跨領域錯位比喻
- 結尾用回望式感性收束，不寫「綜上所述」式總結
```

**將寫作禁則第 1 條擴大**：

```
1. 禁止「不是…而是…」及其同骨架變體：
   - 不是 X，而是 Y
   - 不只 X，而是 Y
   - **真正的 X 不是 A，是 B**
   - **答案不在 X，在 Y**
   - **真正承重的是 X**（單獨可，但不可三段平行使用）
   - **真正的關卡是 X**
```

**新增第 8 條禁則**：

```
8. 禁止過度使用 `——` 接平行三件式列表。每篇全文 `——` 出現次數不得超過 3 次；超過 3 次必須改寫成括號或逗號鋪陳。
```

**新增第 9 條禁則**：

```
9. 禁止把 critic / fact-check 的審稿語直接寫進正文。例如「請當定性整理來讀」「這條因果鏈缺 RCT 直接驗證」「方法論風險是 X」「樣本說明」這類自我審稿口吻。
   修法：把 critic 的提醒消化進論述，或放進文末「誠實邊界」一小段，不要散落在正文每節結尾。
```

### 4.2 Editor prompt 改寫（`prompts/agent-editor.md`）

### 4.4 Pipeline 結構新增「mashbean-accent pass」階段

目前流程：
```
intake → research-draft → fact-check → blog-rewrite → editor → editorial-pass → publish
```

建議改為：
```
intake → research-draft → fact-check → blog-rewrite → editor → editorial-pass → accent-pass → publish
```

新增 `prompts/agent-accent.md`，職責純粹：

> 載入 mashbean-accent skill，把 final/article-final.md 當作素材，依 SKILL.md 的六軸（語氣／構句／段落／幽默／用語／錯字癖）做最終潤色。允許重寫整段，目標是把九項自檢清單命中六項以上。**不負責事實正確性**——前面 fact-check 已處理。

這個階段的關鍵分工：accent agent 不要怕改動句子；前面所有 agent 已經把證據鎖死了，這一階段只動「人味」。

## 5. 優先級

### P0（最關鍵，這週就改）

- **P0-1：把 mashbean-accent skill 接進 writer prompt（4.5）**——這是最大根因。pipeline 不知道 ground truth 在哪，再怎麼改禁則也是繞圈。
- **P0-2：擴大 editorial pass 的 BANNED_PATTERNS 抓「真正的 X 是 Y」「答案不在 X，在 Y」「關鍵不在 X，是 Y」（4.3）**——這是 S1 最痛的點，現在的禁則被 LLM 用同骨架變體繞過。
- **P0-3：在 pipeline 加 accent-pass 階段（4.4）**——前面所有 agent 都被「研究正確性」目標壓著，需要一個專門負責人味的階段。沒有它，accent skill 接進 writer 也會被 critic 反覆磨平。

### P1（兩週內）

- P1-1：editorial pass 加 critic 審稿語洩漏掃描（「請當 X 來讀」「這條因果鏈缺」「待查核」散落正文）（4.3）
- P1-2：editor prompt 改結尾規範與 accent 自檢（4.2）
- P1-3：critic prompt 加跨領域比喻保護條款（4.6）
- P1-4：editorial pass 加 EM_DASH_THRESHOLD（破折號平行三件式抓出來）（4.3）

### P2（一個月內）

- P2-1：writer prompt 第 23 行「開頭必須讓讀者知道這篇要回答什麼」改為「情境定錨」（4.1）——影響大但需要更多樣本驗證後再改，避免反向破壞研究稿的開頭品質
- P2-2：editorial pass 加 accent lexicon 正向掃描（< 3 命中觸發 WARNING）（4.3）
- P2-3：建立 accent-pass eval set，每月用 5 篇成品測試 accent 自檢清單命中率，目標從目前推測 1–2 / 9 拉到 6 / 9

## 附錄 B：手寫樣本 vs pipeline 樣本，開頭三段對照

**手寫**（`2026-03-29-與-ai-agent-生活後的三個啊哈.md`）：

> 仔細記錄一下這兩個月與 AI Agent 協作的雜感。
>
> 這兩個月有三個「啊哈！」時刻，分別是「我的下載項目竟然整理好了！」、「我竟然可以一邊走路一邊動嘴工作！」、以及「我竟然可以慢下來，事情卻好好做好！」。
>
> 寫這篇文的目標不是說我變成了一個多厲害的人，但由於深刻地改變了自己的工作型態，忽然要我說真正改變了什麼，又有點複雜，於是值得好好想想之後，記錄下來。

特徵：情境定錨 → 三個啊哈式經驗排比 → 自嘲式 meta 反思。零論點、零章節預告。

**pipeline**（`2026-04-25-anesthesiologist-ai-agent.md`）：

> 凌晨兩點，腦袋還在跑今天那台刀的麻醉誘導參數。
>
> 身體已經回到家、燈也關了，那條血壓曲線還在閃。明天清晨七點半的肝臟移植要確認血品交叉。後天那位高齡髖部骨折病人，前一晚的抗凝血劑要不要橋接，還沒下定論。手機沒響、沒人 page 你，這顆腦袋根本沒下班。
>
> 麻醉科談累，外人聽到的版本通常是工時、值班、人力。這些都對，只是沒抓到最痛的那塊。真正讓人耗損的，是身分切換不掉。

特徵：情境定錨（這個寫得不錯）→ **「真正讓人耗損的，是身分切換不掉」**（S1 偽裝變體第一現場）→ 第四段直接說「這篇想處理這個結構，順帶處理一個反覆被問到的問題」（章節預告，違反 accent）。

第一段抓到了 mashbean 開頭的味道，第三段就跑掉了。這是 accent 最容易被 critic / editor 壓回去的具體案例：一旦進入「論述」，模型就回到 GPT default voice。

---

**結論**：這不是禁則的問題，是 pipeline 沒有 accent ground truth 的問題。P0 三項做完，下一篇成品的 accent 自檢命中率應該能從目前的 1–2 / 9 提到 5–6 / 9。
